# Airflow-First Evaluation Branch Operating Model

For the data-eng-internal-site branch, we use an Airflow-first operating model to evaluate a pure Airflow workflow for upstream metadata scanning with terminology centered on DAG Runs and mapped tasks, while allowing future development without preserving PowerShell compatibility in this branch. We keep strict file-level storage isolation with two SQLite files under db/ (Airflow runtime metadata in db/airflow-runtime.sqlite and domain observation evidence in db/fec-observations.sqlite), record observation history at per-attempt grain with Airflow attempt identity, and use fail-fast schema compatibility with create-if-missing bootstrap for first run. This was chosen over blended legacy terminology and shared-database designs because the Airflow-first model is easier to evaluate for a developer new to Airflow, produces clearer runtime evidence, and avoids hidden coupling between scheduler internals and domain analytics data.

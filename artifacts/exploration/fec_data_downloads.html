Introduction to FEC Data

The U.S. Federal Election Commission (FEC) provides comprehensive election-finance data to the public. This data is invaluable for researchers, analysts, and developers seeking insights into campaign finance. There are three primary ways to access and utilize this data:

  • Web-based browsing: Ideal for exploring the available data interactively and performing ad-hoc queries.
  • Bulk data downloads: Suitable for in-depth analysis using local database tools like DuckDB.
  • OpenFEC API: A web-based API designed for software developers to integrate FEC data into applications.

Note: This fec-data repository focuses on the bulk data download approach, implementing an ETL workflow for Windows using tools like DuckDB and Power BI.

Challenges in Naming Conventions

"Naming things" is a well-known challenge in software development, and the FEC data sources are no exception. The three access methods listed above often use inconsistent naming conventions, which can complicate data integration and analysis. To address this, it is often necessary to establish consistent naming conventions when working with tools like DuckDB and Power BI.

Medallion Architecture (Bronze-Silver-Gold)

This project follows the medallion architecture pattern for organizing data layers:

  • Bronze: Immutable source files downloaded directly from the FEC bulk data portal. Stored in data/bronze/.
  • Silver: Unpacked and lightly normalized files prepared for analysis. Stored in data/silver/.
  • Gold: Curated and refined tables ready for reporting and visualization. Stored in data/gold/.

For more background on medallion architecture, see Databricks' medallion architecture documentation.

Directory Structure Overview

The FEC data is organized into the following structure to facilitate efficient ETL workflows and analysis:

  • Bronze Data: Immutable source files downloaded directly from the FEC bulk data portal. Stored in data/bronze/.
  • Silver Data: Unpacked and normalized files prepared for loading. Stored in data/silver/.
  • Gold Data: Curated extracts ready for analysis. Stored in data/gold/.
  • Database: DuckDB files containing OLAP tables for longitudinal reporting. Stored in db/.
  • Logs: ETL run logs for debugging and auditing. Stored in logs/.
  • Temporary Files: Intermediate artifacts generated during ETL runs. Stored in tmp/.

This structure ensures that bronze data remains untouched, while transformations and analyses are performed downstream through silver and gold layers. It also aligns with best practices for reproducibility and data integrity.

Schema Design and Mapping

To support both SQL/DuckDB operations and Power BI integration, the following schema-related directories are included:

  • SQL Schemas: Contains DuckDB-compatible DDL scripts for creating and managing database tables. Stored in sql/schema/.
  • Power BI Mappings: Includes schema mapping files and metadata for Power BI integration. Stored in artifacts/mappings/.
  • FEC Schemas: Comprehensive schema descriptions for bulk data files.

These schemas ensure seamless data transformations and compatibility between the ETL pipeline and reporting tools.

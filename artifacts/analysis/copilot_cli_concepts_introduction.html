Copilot CLI Concepts Introduction

A practical architecture + terminology map for experienced developers.

1) Plain-language introduction

Copilot CLI is an AI assistant that works inside your terminal. You type requests in normal language, it can inspect your project, run commands, edit files, and explain results.

Before the architecture view below, here are the three terms used most often:

  • Session: one work conversation with its own context and history.
  • Agent: the AI assistant engine that plans and carries out steps.
  • Runtime: the active setup the session is using (tools, permissions, and current state).

2) Mental model

Inside a session, you interact through a conversation, and the agent carries out work steps using tools, instructions, and optional memory.

User
  └─ Session (container)
      ├─ Conversation (turns/messages)
      ├─ Timeline (ordered events across work)
      ├─ Tasks (agent jobs, subagents, shell commands)
      ├─ Workspace (session files, plan artifacts)
      ├─ Capabilities
      │   ├─ Tools
      │   ├─ Skills
      │   ├─ Plugins
      │   └─ Fleet mode (parallel subagents)
      └─ Context layers
          ├─ Instructions (repo/user policy)
          ├─ Permissions
          └─ Memory (cross-session, if enabled)

3) Hierarchy and definitions

Session (top-level container)

  • What it is: the boundary for one work conversation.
  • Contains: conversation, timeline, tasks, workspace artifacts, usage counters, and active state.
  • Typical commands: /new, /resume, /session, /clear.

Conversation (inside session)

  • What it is: prompt/response turns.
  • Contains: user asks, assistant replies, and attached context references.

Timeline (inside session)

  • What it is: chronological events for work execution.
  • Contains: turn events, tool calls, task updates, status transitions.

Tasks (inside session)

  • What it is: executable units of work.
  • Contains: subagent jobs, shell/background commands, task output/status.
  • Related: /tasks, /fleet.

Capabilities layer (inside session)

  • Tools: primitive actions (read/edit files, run commands, search, fetch).
  • Skills: packaged higher-level workflows with a known interface.
  • Plugins: extensibility integrations managed via /plugin.
  • Fleet mode: parallel subagent execution strategy.

Context/governance layer (applies to session behavior)

  • Instructions: policy and behavior constraints from repo/user instruction files.
  • Permissions: what tools/paths/URLs are allowed.
  • Memory: reusable facts/preferences across sessions when enabled.

4) Persistence map (where things live)

Concept Scope Typical persistence Examples
Session metadata Session Service-backed session record + local active state ID, name, usage, cwd
Conversation/timeline events Session Local session-state files + session history backing ...session-state\<id>\events.jsonl
Session workspace artifacts Session Local per-session folder ...session-state\<id>\plan.md
Runtime process logs Process Local diagnostic logs ...\.copilot\logs\process-*.log
Instructions Repo/User Local files .github/copilot-instructions.md, ~/.copilot/...
Memory User or Repository Cloud/account-level (when enabled) Cross-session preferences and facts
Plugins/skills config User/Environment CLI config (often local), with possible provider-side data /plugin, /skills registrations

5) Operational semantics: /new vs /clear

  • /new: start a new session and switch to it. Prior session remains resumable.
  • /clear: abandon current conversation context and start fresh in place.
  • /resume: switch to an existing session.
  • /rewind//undo: remove last turn and revert its file edits.
  • /session: inspect/manage sessions (list/details/delete depending on version).
